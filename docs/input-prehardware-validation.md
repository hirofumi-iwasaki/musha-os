# 実機前の入力検証と次回の採取手順

## API 4: キー状態の復元

64件の入力FIFOが満杯になった場合も、最新の押下状態を256 usage分保持する。
保存済みイベントを元の順序・時刻で配信した後、配信済み状態との差を解放→押下の
順に補う。それぞれ修飾キーを先に配信する。復元イベントの時刻は読出し時刻。
復元中の新規入力も最新状態へ集約し、古いFIFOより先には配信しない。
入力の生成が止まれば、最大64+256件の読出しで最終状態に一致する。

途中で消えたタップ、入力文字、元の時刻や順序は復元できない。
`lost_key_events()` は復元中に集約したイベント数を飽和加算する。
アプリは欠落件数の変化を検出して、入力履歴に依存する操作を取り消せる。
`set_input_active(false)` 自体は解放を生成しない。切断時は入力元が全キーの解放を
通知する契約を維持し、その解放もFIFO溢れから復元する。
この意味変更に合わせて `API_VERSION` を4とした。

回帰試験はShift+Aの解放取りこぼし、復元中の追加入力、全256 usage、欠落件数の
飽和、5万回の送受信交互実行を含む。実機でFIFO溢れを観測した記録ではない。

## HID mutation/property fuzzing

外部依存を増やさず、固定シードの変異・性質検査を行う。
coverage-guided fuzzingや全入力の網羅を意味しない。

```sh
cargo run --locked --release -p musha-input --example hid_fuzz -- 1000000 7445454
```

引数はケース数と非ゼロの十進シード。記述子は正常配列、1〜8箇所の破壊、途中切断、
0〜4097バイトのランダム列、複数Report ID、位置のずれたキービットマップを混ぜる。
受理した各layoutに24レポートを与え、長さ違い、未知ID、値異常、正常データを試す。

検査する性質:

- panicが起きず、layoutのレポート長が上限内に収まる。
- 不正レポートはイベントを出さず、後続の状態も変更しない。
  正常レポートだけを別decoderへ再生し、以後のイベントと最終解放を比較する。
- 重複押下・対応する押下のない解放・予約usageの出力がない。
- 同一レポートの再送でイベントが増えず、全解放を二度呼んでも解放は一度だけ。

失敗時はstderrにシード、ケース番号、レポート生成直前の乱数状態、記述子の全byteを
出す。同じ引数で再現可能。大量実行はプロセス単位の60秒制限で行う。
CIには各10万ケース×2シードとステップ全体2分の制限を追加した。
時間制限内で終了したことは検査済み入力の結果で、任意入力の停止性の証明ではない。

## 次回の実機確認: T2-D1

詳細なビルド・撮影方法は [T2-D1診断](t2-d1-diagnostics.md) を参照。

1. 使用する成果物のcommit、dirty状態、feature、診断版、EFI SHA-256を
   `build-manifest.json` とともに保管する。T2-D1用featureであることを確認する。
2. Macの型番、USB・Lenovoキーボードの接続ポート、ハブの有無を記録する。
   動作済み構成を基準にし、ポートを変えた試験は別の記録にする。
3. 外付けでA、Shift+A、キーを離した後のA、Escを確認する。
   USB READ / FAT32 READ / APP FILE READ OKも記録する。
4. T2-D1の全ページを順番に撮影する。MODEL、SMBIOS、PCI、BRIDGE、BCE COUNT、
   EARLY/PRE EBS/POST EBS、BAR/capability、完了表示を含め、OMIT/ERRORも残す。
5. 判定は下表で行う。診断結果を得るまで実際のT2通信を有効にしない。

| 観測 | 判定・次の作業 |
|---|---|
| 外付け入力・FAT32読出し成功、診断完了 | 基準機能を保った情報採取成功。内蔵入力の成功とは区別する |
| BCE COUNT 0 | 対象未検出として保存。列挙範囲や機種情報を調べる |
| OMIT / ERROR / 写真欠落 | その部分の証拠が不足。該当ページ・列挙上限・異常理由を確認する |
| EBS前後でBAR/Commandが変化 | 変化を対象BDFと上流bridgeに対応づけ、復旧条件の設計へ反映する |
| BARが非ゼロ | まだUNVALIDATED。サイズ・予約領域・bridge範囲を検証してから使用可否を判断する |
| 外付け入力や読出しが退行 | 後続の通信導入を止め、既知のH19結果との差を調べる |

T2-D1はconfiguration読取までで、HID記述子・内蔵キーのレポートを採取できない。
それらは資源検証、実BCE adapter、queue登録、VHCI列挙を整えた後の別段階で採取する。
その段階ではdescriptor全byte・Report ID/長さ・押下/解放/修飾キー・切断/再接続を
記録し、匿名化したfixtureとして回帰試験へ追加する。現在の合成データだけで
Apple固有の形式や通信タイミングを確定しない。
