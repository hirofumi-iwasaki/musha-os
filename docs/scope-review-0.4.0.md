## Technical dependencies / 技術上の依存

**LE transport and input:** xHCI currently integrates keyboard interrupt and storage bulk sessions (boot/src/xhci/usb.rs:814–826,962–1006). HCI requires control commands, interrupt events and bidirectional ACL bulk, concurrent with storage/keyboard, with bounded scheduling, cancellation and endpoint/DMA lifetime. input/src/lib.rs:13–23 is an 8-byte boot-report state machine; source selection normalizes keyboard usages but does not supply a gamepad event stream. HOGP report IDs/maps, notifications, disconnect releases and reconnect generations must feed goal9 without forcing the USB boot-report assumption. pair=on clearing must preserve unrelated CONFIG keys and the fixed capacity; missing/protected SETTINGS or a failed clear must be visible and must not claim persistence success.

**T2 and Mac storage:** research explicitly distinguishes BCE BAR2/BAR4/queues from xHCI BAR0/TRBs and leaves polling-versus-MSI unresolved. bce host models and input sources are reusable but not hardware proof. Goal14 supplies a stable boot-media observation path; goal15 needs that path to reach/viewer-test internal input. Develop both independently after settings/display baseline; neither blocks other code stages, both block release until their own conditions pass (goal14 permits documented cause/limitation, goal15 requires actual input). Device restart/stop-before-reuse must cover BCE as well as xHCI when promoting continuation.

**Settings/display order:** LoadedImage→FAT32 SimpleFileSystem→bounded CONFIG/key override→GOP choice/SetMode→recapture framebuffer/grid→first permitted display→close all firmware files before final map/EBS. Preserve max-mode tie/layout/query-free rules and distinguish unavailable explicit mode fallback from SetMode failure. These are sequencing changes, not merely a parser addition.

## Validation boundary and VERSION / 検証範囲と版

Existing read-only QEMU viewers cannot establish writes/fsck/protection/cold persistence; compile-only Rust checks cannot establish guest execution/r2 calls; C3 probes cannot establish normal viewer behavior. Screen equality cannot prove DMA stopped (smoke-normal-viewer.py:3–6). New host/QEMU fixtures cover LE HCI/advertisements/SMP/ATT/GATT/HOGP and BCE wire/queue/HID errors, not radio/T2 hardware interoperability. Real formatter routes, I218-V communication, Mac storage/T2, cold/hot pairing and macOS/Windows mount/chkdsk remain owner-run hardware gates.

VERSION=0.4.0 is included in the owner-approved planning baseline; internal crate versions and README banner remain unchanged. prepare-release.py:48–49,163–171 derives/checks against VERSION, distribution.py:20–22 requires optional tag v0.4.0, and package-sdk.py:37 derives the same version. Lightweight checks use --help/import/validation and expected early rejection of mismatched version, old provenance and dirty official packaging, without candidate generation or build. Old v0.3.0 provenance must remain rejected for v0.4.0; that is intended, not a regression. VERSION/README generator changes are runtime changes under approved provenance rules.
