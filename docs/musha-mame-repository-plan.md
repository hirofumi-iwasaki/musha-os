# MushaMAME repository plan / リポジトリー計画

## English

Status: proposal (2026-10-16). The owner has adopted **MushaMAME** in a separate `musha-mame` repository; this document proposes its mechanics, not a working port. No repository, fork, tag, release or cross toolchain has been created. See the [scenario](scenario-mame.md) and [POSIX profile](posix-profile.md).

**Upstream baseline.** Checked on 2026-10-16: the [official latest release page](https://www.mamedev.org/release.html) identifies **MAME 0.289**, tag [`mame0289`](https://github.com/mamedev/mame/releases/tag/mame0289). Pin the resolved upstream commit when implementation begins; do not follow a moving branch in releases. Proposed repository identity: `hirofumi-iwasaki/musha-mame`, subject to owner approval/creation.

**Fork and updates.** Retain upstream history and tags, add an `upstream` remote, and maintain a short Musha patch series rebased onto reviewed stable tags. Record old/new upstream commits, port commit, SDK hash and build environment for every release. Never rewrite an already published Musha release tag. Separate OSD implementation (`src/osd/musha/`), OSD build glue (`scripts/src/osd/musha.lua`) and the driver-subset target (`scripts/target/musha/<subset>.lua`); avoid core edits unless required, keep them independent, and aim to propose general OSD/build improvements upstream. Rebase conflict review and build/tests precede adoption of each upstream version.

**Actual build integration to implement.** In pinned [GENie definitions](https://github.com/mamedev/mame/blob/mame0289/scripts/genie.lua), `targetos` has an explicit allowed list without Musha; OSD selection loads `scripts/src/osd/<osd>.lua`, while target/subtarget selects `scripts/target/<target>/<subtarget>.lua` or a driver filter. Thus adding an OSD directory alone is insufficient: add the Musha OS value and review target/driver-list generation when choosing `TARGET=musha`; do not assume a new target automatically reuses `src/mame` lists. The [makefile](https://github.com/mamedev/mame/blob/mame0289/makefile) treats an explicit TARGETOS as cross-build and forwards build options. Review host generators separately from target compilation. The [toolchain script](https://github.com/mamedev/mame/blob/mame0289/scripts/toolchain.lua) supports compiler/linker/archive overrides but has no Musha preset; add isolated flags and verify generated commands rather than labelling a Linux build as Musha.

**SDK dependency and first milestone.** Download an owner-approved, version-pinned Musha SDK ZIP plus SHA256SUMS; verify its SHA-256 before bounded extraction, record the source commit, ABI revision and toolchain versions in a small dependency lock. No SDK git submodule. `x86_64-musha-elf`, static non-PIC linking, libc, C++ exceptions/RTTI/unwinding, cooperative threads, allocator and enlarged image/arena are **future v0.6 prerequisites, not implemented facilities**. First prove SDK C/C++ startup and exception/thread behavior, then a small driver subset with Musha video/audio/input/time/read-only file backends. Fail build checks on undefined host imports, dynamic interpreter or incompatible NOTE/segments. ROM-independent tests and QEMU precede hardware and performance claims; writable application storage remains a later bounded profile decision.

**Independent release.** Proposed asset `mushamame-<version>-x64.zip`: one ELF, README, `DOCS/` with build/SDK provenance, `COPYING`, required legal texts/notices, installation/limits and corresponding-source location; no ROMs. Publish corresponding source and build scripts for the exact binary under its own release, distinct from musha-os assets. Preserve upstream [COPYING](https://github.com/mamedev/mame/blob/mame0289/COPYING) and per-file licenses. Upstream [README license guidance](https://github.com/mamedev/mame/blob/mame0289/README.md#license) describes the project as GPL-2.0-or-later with other compatible component licenses; a separate repository does not waive their distribution requirements. It also requires permission for MAME name/logo/wordmark use: keep the owner-selected working name, but resolve that upstream permission before public branding/release. No MAME source enters musha-os or its SDK; only scenario documents and independently implemented SDK facilities belong there.

Owner decisions still needed: confirm repository identity/visibility and creation timing; choose Musha version/tag convention (e.g. upstream-tag plus port revision, not adopted); first driver subset/redistributable acceptance data; and the scope/timing of an upstream OSD proposal. Upstream permission and exact release license/source compliance are publication gates. This plan performs no code import or license relicensing.

## 日本語

状態：提案（2026-10-16）。所有者は名称 **MushaMAME**、別リポジトリー`musha-mame`を採用済み。本書は運用案であり移植実装ではありません。repo・fork・tag・Release・cross toolchainは未作成。[シナリオ](scenario-mame.md)と[POSIX profile](posix-profile.md)を前提とします。

**上流基準。** 2026-10-16に[公式最新版ページ](https://www.mamedev.org/release.html)で **MAME 0.289**／tag [`mame0289`](https://github.com/mamedev/mame/releases/tag/mame0289)を確認。実装開始時に解決したcommitを固定し、公開物は移動branchへ依存させません。repo候補は`hirofumi-iwasaki/musha-mame`、所有者の確認・作成待ちです。

**forkと更新。** 上流history/tagを保持し`upstream` remoteを置き、reviewしたstable tagへ短いMusha patch列をrebase。公開ごとに旧新upstream commit・port commit・SDK hash・環境を記録し、公開済みMusha tagは書換えません。`src/osd/musha/`、`scripts/src/osd/musha.lua`、`scripts/target/musha/<subset>.lua`へOSD実装・build glue・driver集合を分離。必要なcore変更は独立patchにし、汎用OSD/build改善の上流提案を目指します。各更新はconflict reviewとbuild/test後に採用します。

**実buildの拡張箇所。** 固定版[GENie](https://github.com/mamedev/mame/blob/mame0289/scripts/genie.lua)のtargetos許可一覧にMushaは無く、OSD lua選択とtarget/subtarget・filter選択も別です。OSD dir追加だけでは足りず、OS値追加とTARGET=musha時のdriver-list生成を確認し、src/mame一覧の自動流用を仮定しません。[makefile](https://github.com/mamedev/mame/blob/mame0289/makefile)の明示TARGETOSによるcross扱いとoption伝達を利用し、host generatorとtarget compilationを区別。[toolchain](https://github.com/mamedev/mame/blob/mame0289/scripts/toolchain.lua)にはcompiler/linker/archive overrideがありますがMusha presetは無いため、専用flags追加後に生成commandを確認します。

**SDKと最初の到達点。** 所有者承認済み固定版SDK ZIP＋SHA256SUMSを取得し、SHA-256照合後に境界付き展開。source commit・ABI revision・toolchainを小さなdependency lockへ記録し、SDK submoduleは使いません。`x86_64-musha-elf`・static non-PIC・libc・C++例外/RTTI/unwind・協調thread・allocator・image/arena拡張は**将来v0.6前提で未実装**。SDK C/C++起動・例外/threadを先に証明し、小driver集合と映像/音声/入力/時刻/読出しbackendへ進みます。host import・dynamic interpreter・NOTE/segment不整合を拒否し、ROM不要試験→QEMU→実機の順。アプリ書込みは後続profile判断です。

**別配布。** `mushamame-<version>-x64.zip`案はELF1本、README、`DOCS/`（来歴/SDK、COPYING、必要legal/notices、導入/制約、対応source所在）でROM無し。exact binaryに対応するsourceとbuild scriptを自repoのReleaseで公開し、musha-os assetsへ混ぜません。上流[COPYING](https://github.com/mamedev/mame/blob/mame0289/COPYING)・個別licenseを保持。[README](https://github.com/mamedev/mame/blob/mame0289/README.md#license)は全体GPL-2.0-or-laterと互換license群を説明しており、別repoでも配布義務は残ります。同READMEはMAME名称/logo/wordmarkに許可を要求するため、所有者採用の作業名を保持しつつ公開branding前に上流許可を確認。musha-os/SDKへMAME sourceは入れず、シナリオと独立実装SDK部品だけを置きます。

所有者の未決事項：repo名/公開範囲/作成時期、Musha版/tag方式（upstream tag＋port版などは未採用案）、初driver集合と再配布可能受入データ、上流OSD提案の対象/時期。名称許可とexact Releaseのlicense/source対応は公開前gate。本書でcode取込みやrelicenseは行いません。
