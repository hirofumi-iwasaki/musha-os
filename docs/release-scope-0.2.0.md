# v0.2.0 開発方針と公開条件

決定日: 2026-10-11。プロジェクト所有者承認。対象ブランチ: `release/0.2.0`。

v0.2.0の中心目標は、**exFATのUSBデータ領域からファイルを選んで読み、内容を画面で確認できること**とする。
既存のFAT32・外付けUSBキーボードを維持し、入力基盤の安定性を高める。
MacBook Pro 2018の内蔵キーボード対応はオプショナルとし、未完成でも必須条件を満たせば公開できる。

本方針はv0.2.0の公開範囲を定めるもので、各機能の実装完了を示すものではない。
内蔵キーボードを中心に進めてきた調査・準備実装は保持し、公開優先順位については本書を優先する。
v0.1.0の公開範囲・検証記録は変更しない。

## 必須目標

| 項目 | v0.2.0の範囲 | 完了条件 |
|---|---|---|
| exFAT読出し専用 | USBデータ領域の識別、ルート直下の一覧とファイル読出し | 連続配置・断片化の両方で元データと読出し内容が一致する |
| ファイル表示 | 外付けキーボードによる選択と、テキストまたは16進表示 | 固定のMUSHA.TXTだけでなく、一覧から選んだファイルの内容を確認できる |
| ファイル読出し基盤 | 選択したファイルを上限付きで少しずつ読む | 全体をメモリーへ載せずに読出し・終了でき、上限や読出し失敗を明示する |
| 入力の安定性 | キー解放、切断、入力元切替、FIFO溢れからの状態復元 | 統合試験で押下状態が残らず、既存の外付け入力を維持する |
| 既存機能の維持 | FAT32、USBストレージ、起動・表示、既存QEMU通信 | 対象範囲の回帰試験が通り、新機能導入による退行がない |

利用者向けの説明は「FAT32に加えてexFATのファイルを読めるようになり、画面で選んで内容を確認できる」とする。
公開時には実際に対応した範囲・上限を併記する。

## exFATとファイル表示の範囲

- 初版は読出し専用。ルート直下を対象にし、長いファイル名も解析する。
- 連続配置とFATチェーンによる断片化を扱う。正常なファイルだけでなく、破損情報、
  途中切断、範囲外参照、循環などでも無制限に処理を続けない。
- 起動用FAT32を維持し、exFATはデータ領域として使用する。exFATからの直接起動は目標に含めない。
- 現行の指定ファイル最大4KiBのsnapshot APIから、選択ファイルを上限付きで逐次読出しできる仕組みへ進める。
- 表示は簡単な一覧・内容確認に絞る。汎用シェル、ファイル編集、アプリ実行環境の拡張は同時に要求しない。
- 長い名前の解析と、日本語などの文字を画面へ描画する機能は分けて扱う。
  初期表示の文字範囲と代替表示方法を仕様化し、未対応文字によって選択を取り違えないようにする。

具体的なファイルサイズ・一覧件数・名前長・読出し時間の上限、セクターサイズ、対応する
exFAT形式の詳細は実装設計時に定め、公開前に文書と試験を揃える。4GiB超ファイルの完全対応は必須にしない。

仕様参照: [Microsoft exFAT File System Specification](https://learn.microsoft.com/en-us/windows/win32/fileio/exfat-specification)。
既存実装の出発点は [FAT32読出し](fat32.md) と [ファイルAPI](file-api.md)。

## MacBook Pro内蔵キーボードはオプショナル

対象はMacBook Pro 2018。BCE・HID・入力切替の準備実装と調査は継続可能だが、
exFATとファイル表示の必須目標を優先する。実機確認待ちやT2通信の難航でv0.2.0全体の公開を止めない。

搭載判断には、実BCE通信・VHCI列挙を経た内蔵キー入力について、通常キー、Shiftとの組合せ、
キー解放、外付けへの切替・復帰を実機で確認し、既存USB処理への退行がないことを要求する。
ホスト上の模擬応答・合成HID・単体試験だけで「内蔵キーボード対応済み」とはしない。

未達の場合は通常起動経路で有効化せず、公開資料に未対応と記載する。
次の実機作業は [T2-D1の情報採取](t2-d1-diagnostics.md)。通信・descriptor採取はその後の段階とする。
[調査資料](macbook-t2-keyboard-0.2.0-research.md)、[登録モデルとメモリー測定](bce-registration-memory.md)を引き継ぐ。

## 今回の必須範囲から外すもの

exFATへの書込み・削除・フォーマット、サブディレクトリー探索、4GiB超ファイルの完全対応、
内蔵SSD、Touch Bar、トラックパッド、全機種・全USBポートへの対応保証は必須にしない。
物理NUCの新規ネットワーク対応や、汎用GUI・シェルもv0.2.0の公開条件へ追加しない。

## 検証と公開条件

1. ホスト試験でexFATの正常・断片化・破損・境界条件と、入力・ファイル読出しの異常系を確認する。
2. QEMUで起動、ファイル選択・表示、FAT32/exFAT読出し、既存のUSB・入力・通信を確認する。
3. 実機が利用可能になった後、MacBook Pro 2018と動作済みの外付けキーボード・USB構成を基準に、
   公開候補のEFIでファイル選択・exFAT読出し・既存FAT32読出しを確認する。
4. クリーンなソースから通常版を作り、診断・故障注入機能を含めない。成果物のチェックサム、
   使用構成、ソースとバイナリーの対応、制限事項、検証結果を記録する。
5. 必須目標が満たされた時点で公開可否を判断する。内蔵キーボードの搭載可否は独立して判断する。

実機を使えない間は仕様・実装・ホスト/QEMU検証を進める。実機確認そのものを完了扱いにはしない。

## 開発順序

1. exFATの対応範囲と試験用イメージを定め、読出し専用解析器を実装する。
2. 既存USB読出しと接続し、FAT32/exFATで共通に使う上限付きファイル読出しAPIを整える。
3. 簡単なファイル一覧・選択・内容表示を実装する。
4. 回帰・異常系試験を揃え、実機確認と公開候補の作成へ進む。

内蔵キーボードの作業はこの順序を妨げない範囲で行い、実機情報が揃った時点で再評価する。
