Decisions:
- Intel routing remains in normal builds with existing vendor/class/EHCI companion/absence gates. Set mask bits with read-modify-write, preserving bits outside D4/DC; check requested bits on readback. A D0 value of 7FF satisfies mask 4FF.
- Attach wait remains 20 ms × 50 maximum, one shared controller budget. CCS and USB3 PLS RxDetect/Polling/Recovery are sampled without PORTSC writes. It runs after controller initialization and port power, following routing.
- Print raw four-word completion, code, expected/returned slot and command pointer; print root/route target, speed ID/name and Slot Context speed ID, plus diagnostic-only input context words. Previous root status is pre-reset; Slot Context uses post-reset ID. No speed mapping change was justified by the existing video.
- Only correlated error codes 4/5/7/17/19/22 may continue. Consume the event/acknowledge it, advance the command producer, require Disable Slot success, then clear DCBAA and continue. Failed-device buffers remain allocated until controller shutdown. Wrong pointer/slot/VF, unexpected codes, timeout and failed cleanup retain controller-wide stop. Storage preference is unchanged.
- Diagnostic status text uses scale 3, matching the right panel, and retains two-second paging. A successful claimed external-file session displays one complete diagnostic cycle before app entry; failed sessions keep cycling. The normal build has no diagnostic delay. No normal pixel reference update: `out/release-final-d/v030-pixels` is unchanged and both absent regressions pass with debug zero.

Validation: host 263 passed; compact framebuffer feature tests passed; QEMU 94 passed (52 normal external, 38 viewer/cooperative, 2 genuine error-injection, 2 diagnostic error-injection). The injected xHC response is completion code 5, followed by confirmed Disable Slot, next-root enumeration and Hello exit 0. Twelve non-debug diagnostic frames captured with zero debug bytes. See `validation.json`. The first injection fixture used p3=0 and failed existing PROTOCOL PORTS validation before reaching the target path; corrected only the virtual topology to p3=1, devices on ports 2/3, and retained the failed evidence. No driver validation was relaxed.

Commands: `cargo test --locked --workspace --exclude musha-boot`; `cargo test --locked -p musha-framebuffer --features compact-status`; release builds with no features, `diagnostics-detail`, and test-only `usb-address-reject` (also combined with diagnostics). `tools/smoke-external-elf.py --normal --boot-from-data --partition-type basic-data/esp`, `tools/smoke-partition-types.py`, `tools/smoke-address-recovery.py` (with/without `--diagnostic`). Individual reports/logs retain paths and invocations. The fault-injection feature is not in either delivered EFI. No ABI/syscall/permissions, Rust guest, launcher, OS return or Mac storage work.

USB deployment: use `tools/update-usb.py` file update only, strict SanDisk model/capacity/volume+partition UUID checks, EFI backup and readback, preserve MUSHA.ELF and Basic Data/FAT32. Deployment result belongs in `out/nuc5-address-recovery/physical-usb/provenance.json`; absence of that record means deployment is pending. No full-device image, hash or partition rewrite.

## 日本語

通常版・診断版を上記ハッシュで作成しました。`01f6efc`＋既存変更を含む未コミット差分です。公開用パッケージ作成・commit/push/タグ/Release操作はしていません。通常版作成後の追加は診断feature内の一巡表示だけで、通常版コードには影響しません。

scope必須6項目は上表のとおり、外部ELF・画面出力・終了/障害・既存ビューアーはQEMU検証、C SDKはコンパイル/Hello実行検証、今回の実機受入は未実施です。C1/C2/C3は今回再実行していません。SDK配布アーカイブも再生成していません。

ルーティングはマスク外ビットを保持し、マスク内だけを照合します。1000ms共通の接続待ちを維持しました。Address Deviceの拒否応答は対応関係を検査して一度だけ消費し、Disable Slot成功後に次の機器へ進みます。停止・中断・タイムアウト・不整合応答や後始末失敗では全体停止を維持します。使用メモリーは制御器停止まで保持し、ストレージ優先は変更しません。

速度一覧のリセット前後を明示し、PORTSC、速度ID/名前、Slot Contextの速度を記録します。既存映像だけでは速度変換バグの根拠がなく、変換は変更していません。診断版の左右を倍率3に揃え、2秒切替を維持。成功時も外部アプリ前に一巡表示するため、その間を撮影できます。通常版の待機は増やしていません。

ホスト263件と縮小文字feature試験、QEMU94件が合格。失敗注入は最初のキーボード／ストレージをコード5で拒否させ、次のストレージからHello→終了0を確認しました。初回試験はQEMUのUSB3ポート0構成が既存検査で拒否されたため、試験構成だけを直して再試験しました。通常版ピクセル参照は変更なし、absent両形式で一致・debug 0です。

USBは既存の専用SanDiskへEFIだけを差し替え、退避・読み戻し・取り出しを行います。成否は上記provenanceで確認します。USB全容量の書込み・ハッシュ、パーティション変更は行いません。NUC5での根本原因と冷間起動成功は新しい採取結果待ちです。
