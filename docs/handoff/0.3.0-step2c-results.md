### Decisions and rationale

- Default builds select the external path. `external-elf-probe` enables only `qemu-debug`; fixed C1 assembly, C2 embedded ELF and C3 lifecycle remain opt-in. The explicit external/embedded feature combination is rejected by the build (`out/external-elf-2c-final/mutual-exclusion.json`).
- Normal linked EFI inspection uses the link map and binary: no fixed-payload symbols, lifecycle or whole embedded SDK ELF. `out/external-elf-2c-final/normal-inspection.json` records file size 458,752 bytes and resident size 17,596,416 bytes. The 16 MiB staging buffer occupies zero-fill memory; loaded-image bound is 32 MiB. [Memory rationale](../external-elf.md) explains UEFI placement, the reserved-excluding 32–256 MiB arena, DMA allocations and diagnostic RAM testing. Recorded ranges are checked in the debug harness; they are not fixed physical addresses.
- Console is 80 columns × 24 rows, oldest-row discard, printable ASCII/newline and `.` per other byte. Copy through C2-owned aliases precedes rendering; UTF-8 validity, log limits/permission/return values and ABI values remain unchanged. Exit status is signed 32-bit. Loading, exit, fault and refusal strings are specified in [usage](../external-app.md).
- External readiness is OS_READY EXTERNAL_APP → APP_ENTERING → first query APP_RUNNING. Debug cases check ordering and no FILE_VIEWER readiness, plus USB/network stop before entry. Exit/fault halt; normal OS return is not added.
- Duplicate discovery preserves existing medium selection: only the selected medium presents the MUSHA.ELF duplicate rejection. Other duplicate names remain filesystem failures; no alternate-medium launcher is introduced.
- Keep the 5000 ms file deadline and 64-byte–16-MiB admission limit. The required one-per-size observations in `out/external-elf-2b-accepted/report.json` are 16 KiB: 24 ms complete; 1 MiB and 16 MiB: 5000 ms incomplete. Full-read times for the latter are unknown. Hello (13,312 bytes) completed in 30 ms in that run. **16 KiB is the largest tested completed size**, not a universal throughput promise; 16 MiB is not a practical five-second guarantee. Later 16 MiB runs can fail at the lower USB transfer deadline. The functional timeout fixture uses 1 MiB to isolate the file-reader deadline.

### Failed attempts, retries and open gates

- `out/external-elf-2c-accepted/report.json`, `external-elf-2c-verified/report.json`, and `external-elf-2c-complete/report.json` are partial/failed suites, **not full passes**. A padded 16 MiB read sometimes reaches USB TRANSFER TIMEOUT before the reader deadline, so elapsed instrumentation is unavailable or the expected file-deadline text differs. This also occurred in an isolated run; it is not attributed solely to parallel QEMU load. Preserve these logs. Keep measured/censored size results separate; use a 1 MiB timeout fixture, then rerun the complete functional table in `external-elf-2c-functional`.
- The viewer timeout harness initially read a partial BOOT_TIMES line. Waiting for its newline fixed the test race; the timeout retest passes. Guest behavior was unchanged for this fix.
- The first link-inspector draft treated an OS Hello string / ELF validator magic as embedded-app evidence. These legitimate constants made that assertion invalid. It now checks fixed-payload symbols, lifecycle and the full SDK ELF, plus PE zero-fill bounds; final inspection passes.
- Hardware throughput, cold boots, release-profile clean committed build, relocated SDK distribution and publication gates remain open. The unoptimized debug-profile vector 8 issue remains open. No release readiness or physical test result is inferred from these local checks.
