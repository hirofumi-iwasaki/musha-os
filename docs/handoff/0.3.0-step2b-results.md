The console retains 80 columns × 24 rows and discards the oldest row on overflow. Printable ASCII and newline are rendered; other bytes become `.` (the existing viewer convention). UTF-8 validation, owned-alias copy, 4096-byte log limit, permissions and return values are unchanged. Exit uses the existing signed 32-bit status. Display strings: `Loading MUSHA.ELF ...`, `MUSHA.ELF exited: status <n>`, `MUSHA.ELF faulted` with vector/error/RIP/RSP, and `MUSHA.ELF rejected: <reason>`. The first query marks APP_RUNNING after OS_READY EXTERNAL_APP and APP_ENTERING; no static viewer entry is recorded on this path.

FAT32/exFAT catalogue parsing already rejected duplicate names before publishing the file service. It now retains a bounded 12-unit name prefix in an internal error (still rejected); only a matching MUSHA.ELF prefix triggers external rejection presentation. Other duplicate names retain the existing failed-filesystem/viewer outcome. SDK generated Rust formatting was aligned with its generator; no ABI values changed.

One run per padded FAT32 size: 16 KiB completed in 24 ms; 1 MiB and 16 MiB each reached the 5000 ms deadline without completion. These are deadline-censored observations, not full-read times. Hello is 13,312 bytes and completed in 30 ms in all three Hello cases. Five seconds is unchanged. The largest tested size that completed within the deadline is 16 KiB; no general device-independent maximum is claimed.

Failed attempts: the initial host console test needed an explicit u32 pixel type; the first QEMU suite stopped at duplicate because the filesystem had rejected its catalogue before the boot-file reader saw it (`out/external-elf-2b-first/report.json`). The new specific duplicate error required updating the existing exFAT duplicate-error assertion; the old expectation failed in `host-retest.log`. After corrections, the full 26-case suite and all 244 host tests passed. Superseded runs are not acceptance evidence.

Normal pre-2c EFI SHA-256: `2d76535359ab9c41f49a848be4f84889df764b6f791e53d2e16d5eef7a4c43cd`. Pixel reference: `out/v3-normal-final-pixels/list.ppm` and `text.ppm`; list/open/back match, debug output 0 bytes, virtual images unchanged.

Excluded feature changes: none. No new syscall/ABI value, Rust guest, normal OS recovery, launcher, physical USB, Release, tag, PDF or v0.2.0 artifact operation. Normal integration, full probe/viewer/cooperative regression, final memory rationale and user documentation belong to 2c. Hardware acceptance remains outstanding.
