# v0.2.0 作業順と完了条件

2026-10-11開始。対象は `release/0.2.0`。
[公開方針](release-scope-0.2.0.md)に従い、exFATからファイルを選んで表示する機能を優先する。
内蔵キーボードはオプショナル。実機不在中はホストとQEMUで進め、実機合格とは区別する。

| 順序 | 作業 | 完了条件 | 状態 |
|---|---|---|---|
| 1 | 対応範囲とAPI契約を設計 | 上限、名前、エラー、媒体寿命、入力との協調を文書化 | 初期設計済み。工程4でAPIを確定 |
| 2 | exFAT試験データを準備 | 正常・断片化・長い名前・空ファイル・破損を再現し、独立した実装で正常像を検査 | 初期セット検証済み。境界・partition形式は追加予定 |
| 3 | 読出し専用解析器 | boot、bitmap、up-case、entry set、連続/FATチェーンを検証し、元データと一致。破損・循環で停止 | 未着手 |
| 4 | FAT32/exFAT共通の逐次読出し | 一覧、選択ID、open/read/close、媒体世代、Again、切断、キャンセルを試験。既存snapshotも維持 | 未着手 |
| 5 | USBとQEMUで接続 | BOTを状態機械化し、入力・通信と協調。内容一致、切断、timeout、DMA停止を確認 | 未着手 |

| 7 | 統合回帰と公開候補 | FAT32/exFAT・入力・通信を回帰し、通常版とチェックサムを用意。実機で承認後に公開 | 未着手 |

## 実装の進め方

最初の単位は工程1と2。詳細は [exFATと逐次読出し設計](exfat-design.md)。
[工程2の初期イメージと検証記録](exfat-fixtures.md)に工程3の解析器を接続し、その後GPT/MBR、境界値、追加の破損ケースへ広げる。
生成器と解析器が同じ誤りを共有しないよう、外部のexFAT検査器と既知の内容・ハッシュを併用する。
合成イメージだけでなく、公開前には標準フォーマッター由来のイメージでも確認する。

現行USBは起動時の同期読出し後にストレージを停止する。
画面操作から同期読出しを呼び出すだけでは入力を妨げるため、工程4では非同期契約を先に決め、
工程5でUSB処理を分割する。ディスク待ちをアプリのstepへ持ち込まない。
工程3はホストの同期ブロック読出しで検証できるが、媒体依存を解析器へ埋め込まない。

各工程で関連試験と文書を更新する。ホスト試験、QEMU試験、実機試験の結果は分けて記録する。
実機が使えるまでは専用USBの更新を必要としない。
